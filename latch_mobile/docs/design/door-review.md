# Door screen

The user’s [720 × 1560 phone screenshot](door-before-compact.png) is the baseline for this scoped density refinement. Preserve its Latch mark, Space Grotesk type, red accent, Account control and plain light/dark background. The approved change is to replace the oversized door heading/illustration panel with compact icon-led rows suitable for multiple doors. The earlier [1016 × 1548 generated concept](door-target.png) is superseded; it is not evidence of the current layout or a runtime capture.

The header places **Account** beside the mark. It opens the existing animated `AppModal` as **Your account**, with the full selectable email, **Sign out** and **Cancel**. Opening the dialog only reveals account controls; sign-out executes only when its explicit action is pressed. Android Back and backdrop dismissal use the same close callback as Cancel. Account remains available on loading, unavailable and unconfirmed-result states, but is disabled while an unlock request or another confirmation is active. No drawer, additional route or native dependency was introduced.

The ready state has a general **Door access** heading and one compact surface: a 32 × 40 dp door icon, an 18 sp door name, full organisation/site/zone context and a labelled **Unlock** action with a 48 dp minimum touch target. A short readiness line sits beneath it. There is no separate hero title or large decorative illustration. The identity and action use a wrapping layout so narrow widths and large system text can move the action below the identity; location text is allowed to wrap rather than being truncated. TalkBack retains the contextual **Unlock COE Door** label and the pending/busy state.

Multiple matches use the same door identity in a grouped picker, separated by rules and followed by chevrons. Selecting a row still only selects its context; unlocking still requires opening the confirmation and explicitly choosing **Unlock**. **Change door** returns to the picker. Discovery remains scoped to the existing COE Door matching rules; this visual change does not broaden provider access. Icons are decorative and never imply that a physical door is open or locked. Existing permission checks, cooldown and unknown-result acknowledgement are preserved, and request results stay visible outside the door surface.

Pull-to-refresh replaces the ready-screen **Refresh access** button. The native indicator uses the action red and themed surface. Content stays visible while rechecking access, and an available selected context is restored using its fresh choice key. Unlock and context changes are blocked while refreshing; overlapping refreshes, confirmation, pending unlocks and acknowledgement saving are guarded. An unavailable state retains an explicit **Try again** action. The sign-in screen has no refresh control, and the COE-only discovery scope is unchanged.

S4 journeys cover distinguishable North/South door selection and confirmation, Account actions, pull-to-refresh without dispatch, content and selected-context preservation, duplicate pulls and pending/unknown-result recovery. Refresh tests exercise the real React Native JS control with its native bridge mocked; they do not simulate physical swipes. The new refresh and selection-preservation journeys were observed red before implementation. All 150 tests across seven suites, lint, typecheck and an Android production bundle export pass. The export is a packaging check, not an installable APK or a native visual check.
